the verify gap

Bold reframe: The check that should catch the failure usually runs – but it looks at the wrong layer. Verify gap is the distance between where a failure originates and where your verify stage actually looks.

Opening scene – LangChain SQL agent, Dec 2025

The agent planned a SQL query (PLANNING), called `sql_db_query` (TOOL CALL), but the schema wasn’t attached to the retrieval context (RETRIEVAL). It executed a malformed JSON payload (EXECUTE), verify checked only that the answer was a non‑empty string (VERIFY), and output passed (OUTPUT). Root cause: RETRIEVAL. First visible: VERIFY. The verify stage didn’t inspect the tool‑call trace, so the gap went undetected.

“The verify stage is where we *think* we catch things – but it’s often where we *realise* we weren’t looking.”
— coined term verify gap

the hidden connection

Eval pass ≠ trajectory safe.

credibility & nuance

The LangChain postmortem cited a single log line – the malformed query param – and the fix added schema validation at EXECUTE. The AutoGPT team changed verify to check namespace before memory reads. The strongest counterargument: “we have end‑to‑end tests.” But end‑to‑end tests don’t exercise intermediate tool‑call schemas or memory namespace collisions; they assert final output. That’s the verify gap.
