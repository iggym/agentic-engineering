In February 2025, a developer using CrewAI to automate competitive analysis watched their system produce a polished, confident, and entirely wrong report. The research agent had overstated a competitor's product launch — "announced" became "shipped." The drafting agent accepted this as fact. The review agent, receiving only the draft rather than the original sources, found the writing clear and the reasoning sound. The report made it to the stakeholder before anyone noticed. Three agents, one corrupted premise, zero alarms.

Which agent failed? Hold that thought.

Your shared-context architecture isn't making your agents collaborative. It's making them contagious.

Where the Fire Starts

Trace the execution mechanically. Planning assigns research to Agent A, drafting to Agent B, review to Agent C. Agent A calls a web search tool — retrieval works, five sources returned, all real. But Agent A's synthesis overstates a claim from one source. That synthesis, not the raw retrieval results, becomes Agent B's input context. Agent B has no mechanism to distinguish A's inference from A's evidence. By the time Agent C sees anything, the original retrieval context has been discarded entirely — only downstream conclusions remain, unrecoverable and unchallengeable.

The root cause sits at the context-passing boundary between A and B, where a synthesis was promoted to a premise without a validation gate. Not the tool call, which retrieved correctly. Not the output format, which was well-structured. The pipe between them. In a single-agent system, that same synthesis error would have been the final output — visible, correctable, bounded. In a multi-agent system with shared context, it became an invisible input to the next agent, amplified rather than contained.

Now go back to the question: which agent failed? The answer is none of them individually. The architecture failed — by passing unvetted conclusions as context instead of passing evidence with attached confidence signals.

Taxed to Death

Microsoft's AutoGen team documented that in group-chat configurations with four or more agents, shared conversation history caused later-speaking agents to degrade in output quality. The cause wasn't model weakness — over 60% of the context window was occupied by prior agents' exchanges, leaving insufficient room for the current agent's own task reasoning. The team's fix was to implement per-agent context windows that only included turns relevant to each agent's assigned task, not to improve prompts or swap models. The group chat abstraction hides this completely: you see "four agents collaborating" when what's actually happening is each agent paying a growing context tax for every agent that spoke before it. Add a fifth agent, and the first four all get slightly dumber. No prompt engineering, no model swap, no additional tool call can recover that lost context budget — it's gone, spent on upstream noise.

A LangGraph user reported in February 2025 that a child subgraph inherited the full parent state, including irrelevant fields from a prior research step — task descriptions, intermediate outputs, even the original user query in its unprocessed form. The result: a code-generation subagent hallucinated references to libraries it had never been asked to use, because those library names appeared in the upstream research context. The state channel architecture merged everything by default; isolation was opt-in. A LangGraph contributor described state channel scoping as "one of the most commonly misunderstood features" in the framework — which tracks, because the default behavior does the opposite of what production isolation demands. The user's fix was four lines of explicit state channel configuration. Finding it took two days. Two days spent debugging a code-generation agent that was never the problem.

Collaboration cost is paid in context budget, and nobody's tracking the balance.

Three incidents, three frameworks, one pattern: shared context is the default, isolation is an afterthought, and the cost is invisible until a corrupted premise propagates far enough to become visible at the output layer — by which point the original source of the error has been erased from the context chain.

This is the same class of failure that made global mutable state toxic in software engineering. We learned decades ago that unrestricted shared state makes bugs invisible until they're catastrophic. Agent context is shared state — it just has a more forgiving name and a much larger blast radius.

Every subagent you add to your system is both a worker and a potential contaminant, and your architecture treats these two roles as identical.

The failure wasn't in the model — it was in the plumbing between models.

Argue the Other Side

The strongest counterargument: shared context is the entire point of multi-agent systems — agents need to build on each other's conclusions, and strict isolation would force redundant work and break coherence. This is reasonable. Multi-agent systems without any shared context would indeed be crippled — every agent would start from scratch. But building on conclusions requires distinguishing those conclusions from their underlying evidence, and raw context passing destroys that distinction. The AutoGen team's own fix confirmed this — they changed the architecture, not the prompts. You can share conclusions without sharing the full context that produced them: pass the claim, attach a confidence score, preserve a pointer back to the originating source. That isn't isolation. That's hygiene.

What to Check Now

Does each subagent receive only the context slices it requires, or the full upstream state by default?
Can a downstream agent trace any claim back to its originating retrieval source, or does it only see another agent's synthesis?
Does your framework's default state-passing behavior isolate or merge — and do you know which without checking the docs?
Have you measured per-agent effective context budget after subtracting shared-history overhead?
Is there a validation or confidence-gating step between any agent's output and the next agent's input context?

Within 24 hours, pick your most critical multi-agent pipeline and log the exact context payload each subagent receives at invocation. If you see the full upstream state where a targeted slice should be, you've found your bleed point — and fixing it will prevent failures you didn't know you were having.
